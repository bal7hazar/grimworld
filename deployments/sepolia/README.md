# Sepolia deployment records

One JSON file per deployment, `<YYYY-MM-DD>-<short sha>.json`, written by `scripts/sepolia_deploy.py` and committed by the orchestrator after the run (OPERATIONS §7, "Deployments"). A record holds the network and chain id (`SN_SEPOLIA`), the commit of `main` the classes were built from, the CI artefact they came from (run URL and name `contract-classes-<sha>`) with its `build-root.json` (checkout root, commit, Scarb, OS: FND-12), each declared class name with its class hash, each contract with its address (Registry, TxHashFate, Hub, Instances), the ids of the seed's records, the number of transactions sent and their total fee (summed from the receipts). It holds no key, no RPC URL and no account address: the script never prints, logs or writes the value of any secret `STARKNET_*` variable (the RPC URL, the account address, the key). (`STARKNET_NETWORK` is a public name and is not redacted. Limit: an RPC URL whose secret part is shorter than 12 characters is not supported; the redactor hides path, query and `;params` pieces from 12 characters. Another limit: a secret number glued to another hex run (`0x<address><key>`, `ab<address>`, a decimal form glued to more digits) is not hidden, because the token regex takes the whole run, which equals neither number.) It is produced by running the script with the account in those variables (used by name), after the chain id check (`SN_SEPOLIA`) and from the artefact of a push to `main` (`--commit <sha>` or `--artifact-run <id>`; `--dry-run` stops before the first transaction); the order is §7's "Deployment order". A `--devnet-rehearsal` record says `"rehearsal": true` and is never written here.

When two records share a date, the newer is the one whose `artefact.run` id is higher (GitHub run ids only increase); that is how `client/app/src/chain/networks.test.ts` picks the current record. Today `2026-10-15-a1b1d16` is newer than `2026-10-15-c25a426`.
