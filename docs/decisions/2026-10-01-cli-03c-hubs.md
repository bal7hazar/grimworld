# D-178: CLI-03c, the hubs and the transitions to and from an instance, on fixed data

| | |
|---|---|
| Asked by | The owner, 2026-10-01, after testing CLI-03a's sandbox (moves, sight, the edge of a zone) |
| Decided by | `[Fable 5.1]` project manager, under D-128 (a task of the client's plan pulled forward; the design is design/11's) |

## The client's plan, as it stands

CLI-01 (the shell: a burner account, the chain through starknet.js, the indexer's subscription;
for the browser first, D-152), CLI-02 (the simulation mirror, from ENG-02/05/07's vectors), CLI-03
(CLI-03a's sandbox wired to the mirror and the chain), then CLI-05 (combat UI, Phase 2), CLI-06 (hub
UI: board, trainer, build editor, character sheet, Phase 3), CLI-07 (inventory, loot, alchemy,
Phase 4), CLI-08 (world map, onboarding, Phase 5). The hubs were to come with Phase 3's quests.

## Decided

**CLI-03c, on track CV, now**: the hubs and the transitions, **on fixed data**, as CLI-03a did for
rooms, so that the owner sees and iterates by eye before the chain is wired.

| In | From |
|---|---|
| The hub screen of design/11 *Hubs*: an illustrated town with places to tap (the pack's buildings through the local atlas, shapes otherwise, D-73), present adventurers as decor, the row of services as entries (the screens behind them are stubs: Guild, Trainer, Smith…, Market, Vault, each a titled empty screen with a back) | design/11 Hubs, design/10 |
| **An outpost**: the same screen, smaller, fewer services (design/01, design/09: which services an outpost has) | design/01, 09 |
| **The Gate screen**: the map of where to go from this hub (the gates of the registry's test region, ENG-03's seed: a zone, a dungeon), the build and belt summary, a last check | design/11 Gate; ENG-03's `contracts/seed/` as fixed data |
| **Hub → instance**: choosing a gate, the entry moment (the entry draw's suspense, design/02; ADR-0002), the instance opening on the entry chunk with the sandbox's renderer (CLI-03a) | design/02 *Entering*, design/18 |
| **Instance → hub**: through a hub gate (standing on it, D-148), `travel_back`, or defeat (design/02 *Ending an expedition*): the closing report (results: experience, loot, quest progress, the belt credited back) as a screen, then the hub | design/02, design/07, D-141 |
| Phone and desktop layouts of design/11 | |

**Out**: any rule (the placeholders stay in `sandbox/placeholders.ts`, each marked `PLACEHOLDER until
CLI-02`); the chain (CLI-01); the real screens of the services (CLI-06, CLI-07); the world map
between hubs (CLI-08). The transitions produce **intents** (`enter gate g`, `leave`), the fixed
data answers them. The view-state rule of the mandate §6 holds.

**Design**: design/11 *Hubs* is the specification; what it leaves open (the look of an outpost, the
entry moment, the report screen's content) is drawn in the sandbox and **decided by the owner's
eye**, then written into design/11 by the lot, one line each. Audit: none (D-177; the owner sees the
lot). Opus 5.5; Nexus `--class browser` for the visual checks.

## What would reverse it

The owner preferring the world map (CLI-08's content) before the hub screen.
