# D-149: the Mac takes tasks of the game's track

| | |
|---|---|
| Asked by | The owner, 2026-09-29: the VPS is the bottleneck, the Mac has room (12 cores, 64 GB, 5 agents) |
| Decided by | `[Opus 5.5]` project manager, under D-128; reversible by the owner |
| Mandate | [ORCH-client-visual](../briefs/ORCH-client-visual.md) §8 |

## Decided

1. **One orchestrator on the Mac**, track CV's, its mandate widened by *tasks lent by the game*;
   not a second one. A second session would spend the app account's weekly quota (87 % on
   2026-09-29) for work one session can hold, and would be a third party writing the game's files.
2. **Whole tasks, lent by name**, that need neither Sepolia nor a file the game's orchestrator is
   writing. The Mac's orchestrator briefs, launches, reviews, has audited and merges a lent task;
   the game's orchestrator does not launch it.
3. **First: IDX-01, the indexer.** It depends only on ENG-01's frozen events (and SPK-11's
   prototype), lives in its own folder, is tested on a local node, and is off the path the VPS is
   running (ENG-06, then ENG-05 and ENG-07, which wait for the map library).
4. **Not lent now**: the engine tasks (`contracts/`, one chain the game's orchestrator runs in order;
   two writers would collide), ENG-R1 (shown to the owner with the game's orchestrator), anything
   that sends to Sepolia. Next candidates: CLI-02 after ENG-02, `claude` audits of the game's lots,
   spikes without Sepolia.
5. **Before a task that builds Cairo on the Mac**: Node aligned on the pinned 24.21 (the Mac has
   22.22) and the Cairo toolchain of `scripts/setup-toolchain.sh` checked by a build of
   `contracts/`.

## What would reverse it

The owner preferring a second orchestrator; a lent task found colliding with the game's; the
map library, which holds the game's critical path (LIB-05 before ENG-02 and ENG-05), wanting the
Mac's room more than the game does.
