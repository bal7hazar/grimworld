The service deploys and funds a burner once per key, the key server-side. Its caps are environment
variables; FND-08 chose the defaults:

| Cap | Default | What it bounds |
|---|---:|---|
| Funding per burner | 2 STRK | a player's first transactions |
| Fee cap per funding | 0.5 STRK | a funding's cost |
| Burners per UTC day | 50 | **125 test STRK a day handed to the node; 127.5 a day by inclusion** (one execution per nonce at a time) |
| Per client per rolling hour | 3 | 7.5 STRK a client-hour |

**Recommendation:** accept these defaults for the first Sepolia playtests (test tokens only), and
revisit the day's budget before a playtest open to strangers, as D-137's reversal condition says (a
funded burner can be emptied by its holder: the drain above is exactly that).

**The note N-1, for OPS-01:** the service refuses to start while any lock exists (stale ones
included), so only one service owns a state file and its funding account. Removing a stale lock is
an operator's step, and two operators doing it at once could both start a service. OPS-01's runbook
names one operator for it, on the one host that holds the state file.

**Recommendation:** write N-1 into OPS-01's row and brief.
